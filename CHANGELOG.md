# Changelog

## Unreleased

The embedding queue is described accurately, and `haunt health` reports the numbers needed to judge it. The agent skill told agents that hooks "defer embeddings to a persistent process"; no such process exists. Nothing drains the queue on a timer or in the background: `haunt bootstrap` drains up to 500 rows per namespace per run, `haunt maintenance` one batch of 64 (ceiling 100), and a non-deferred write up to 32 as a side effect. Recall never drains, and hook writes — the highest-volume producer — never drain either, so a hook-only namespace stays behind until an operator runs one of the three. The same correction lands in README's "What is and isn't automatic", which previously did not mention embeddings at all, and in the docstrings and comments that variously claimed a persistent process, a background drain, that `recall()` drains, and that hooks run under a haunt-imposed watchdog. There is no such watchdog in this repository; whatever timeout applies is the host editor's.

`stats()` gains `memories_embeddable`, `embedding_coverage` and `embedding_oldest_pending`, and `haunt health` prints them. The denominator mirrors the enqueue predicate exactly — `skip_embedding=0` and non-blank content — so full coverage can actually reach 1.0, where `memories_embedded / memories` lands short forever on a namespace holding policy-excluded rows. Coverage is `None`, never `0.0`, when there is no denominator or no vector index: an FTS-only namespace and one that has never embedded would otherwise both read as "0% coverage, unhealthy", which is the opposite of true. The oldest queued timestamp is the only one of these that separates "a drain just ran" from "this queue has been stalled for days". No threshold is attached to any of them; BACKLOG D10 records why, and what evidence would let one be set.

Editor host config refuses a hook command a shell would not run verbatim, and refuses a config file outside the current home. Hook entries are written as one unquoted `command` string that both editors execute through a shell, so a `HAUNT_HOME` containing a space produced "no such file or directory" and capture stopped with no error, while one containing `$(...)` executed on every hook event. Installation refuses such a path rather than quoting it, and `HAUNT_ALLOW_UNSAFE_HOOK_COMMAND=1` (exactly `1`, and deliberately not the alternate-home variable) writes it anyway for a host that execs hooks directly: MCP entries in the same files are spawned argv-style, where added quotes would become part of the path, and nothing in the config distinguishes the two at read time. Separately, the alternate-home guard judged the haunt home being written *into* the config but never the config file itself, which resolves through `CLAUDE_CONFIG_DIR`, `CURSOR_HOME` or `CURSOR_HOOKS_JSON`; with `HOME` redirected and one of those still pointing at the real config, the guard passed and the temporary home landed in the operator's global settings anyway. The alternate-home and foreign-target guards share `HAUNT_ALLOW_ALT_HOME_HOST_INSTALL=1`; the hook-command guard has its own `HAUNT_ALLOW_UNSAFE_HOOK_COMMAND=1`, because consenting to bind a temporary home into global config is a different decision from consenting to a command a shell may mangle. All three now derive from one `HostInstallRefused` base and are caught as a category by `haunt install`, `haunt cursor-install`, `haunt doctor` and `haunt bootstrap`, which skips and reports rather than aborting. `install_all_hosts` preflights every adapter before any of them writes, so a refusal cannot leave Cursor bound and Claude Code not.

`haunt doctor`'s dangling-hook remediation said `haunt install`, which is refused in the situation that produces the message. It now says `unset HAUNT_HOME && haunt install` and explains why the unset matters.

Retrieval ties are reproducible across ingests. Every tie-break in the recall path keyed on `memory_id`, which is a fresh uuid4 per write: the ordering was total within a run and re-rolled on the next one, so the same corpus scored twice returned the same two exactly-tied documents in either order. One LongMemEval question oscillated between gold rank 5 and 6 across ten runs of identical trees — bm25 equal to the last bit, order decided by whichever uuid4 sorted first. FTS candidates, native and fallback vector candidates, and the fused set now break ties on `content_hash` — a pure function of the stored text — before falling back to `memory_id`, which stays the final component so the order remains total. This changes no score, threshold, `RRF_K`, candidate-pool size or `k`, and can only reorder rows whose primary key is exactly equal; every ordering it can produce was already reachable before, the dice are simply no longer re-rolled. The advertised `ordering.ties` becomes `content_hash_asc_then_memory_id_asc`. Rows written before schema v10 and not yet backfilled hold a NULL `content_hash` and still order by id among themselves (register item R7).

`haunt bootstrap` now writes `~/.haunt/bin/haunt` alongside the three existing wrappers, and the desktop shortcut prefers it. The shortcut resolved its target with `shutil.which("haunt")`, which resolves once at icon-write time and then freezes; on a machine with a pyenv shim ahead of the haunt venv on PATH that pinned the launcher to an interpreter whose `sqlite3` was built without loadable-extension support, so the console opened and no vector search worked. The wrapper re-execs the interpreter haunt is installed into, survives PATH changes and venv rebuilds, and is rewritten idempotently by every `haunt install`.

Desktop launcher paths are quoted. The macOS `.command` interpolated the executable into double quotes, where a path containing `$(...)` or a backtick runs command substitution before `exec` sees it; it now single-quotes. The Linux `Exec=` line was unquoted, so any path containing a space — this project's own checkout lives under `GitHub Repos` — was split into arguments and the entry silently did nothing; it now quotes per the Desktop Entry Specification. The Windows `.bat` escapes `%`.

The runtime model-artifact check no longer lives in the evaluation harness. `haunt.embed` verified the cached BGE-M3 bytes by importing `verify_local_hybrid_cache` from `abstention_eval`, through a function-local import that existed only to dodge an import cycle — so every production model initialization pulled in the E6 harness and, with it, `recall`, `rerank` and the whole `urllib`/`ssl`/`email` stack that only its network-deny harness needs. (`haunt.store` was already loaded either way — `haunt/__init__.py` imports it — so it was never part of the delta.) The artifact constants, canonical manifest hashing and cache verifier now live in `haunt.model_manifest`, which imports the standard library and nothing else; `abstention_eval` re-exports every name, so E6 evidence still attests one implementation. Verifier behaviour is unchanged byte for byte across valid, missing, extra, zero-byte, wrong-size, wrong-hash, quantized, root-level, symlinked and missing-sidecar caches, capped and uncapped, and the fail-open legs still fail open. The model-load path costs 32 fewer modules net (296 to 264): the first cache verification used to pull 33 in and now pulls none, at the cost of one module bound at import. Importing `haunt.embed` alone therefore goes up by one, not down — the old import was function-local and never fired at import time, so the saving belongs to the verification path, not the import. The manifest's own schema version is a separate constant from the E6 fixture schema version, which were one shared `1`: bumping either had silently invalidated the other.

Namespace ownership is decided inside the transaction that publishes and binds it. Two repositories whose lossy labels collide could both infer before either registered, both see the label free, and both end up bound to one namespace. `_foreign_repository_owner()` now runs on the publishing connection, so the first read that can see the winner's binding is also the one that decides, with no window in between. The loser forks to `label-<digest>` over its own strongest identifier — remote identity, else checkout path — which is what inference already uses.

That fork lands the loser on the same label it would have inferred had it simply run second **only while that fork target is free**. When a third repository already owns it, the raced loser has no candidate left and fails closed with `NamespaceCollisionError`, while a sequential loser would have inferred the fork label first and forked once more to `label-<digest>-<digest>`. Both refuse to commingle; they do not agree, and the refused caller does not converge on the sequential outcome by retrying — it fails closed identically until an operator runs `haunt namespace reconcile`.

Only a *derived* label is ever contested. A label a human typed is honoured as typed: `haunt init team --repo A` then `haunt init team --repo B` binds both to `team`, because deliberately sharing one namespace across checkouts is a supported workflow rather than a collision. `HAUNT_NAMESPACE` and `haunt init NAME` with no `--repo` already reached registration naming no repository; `haunt init NAME --repo PATH` was the one path that paired a chosen label with a repository, and it no longer reroutes to `team-<digest>`. The older one-namespace-per-repository rule is unchanged: naming a namespace cannot move a checkout that already has one.
Global editor host config is bound only from the default haunt home. `install_all_hosts()`, both host adapters and `install_desktop_icon()` now refuse when the home about to be written is not `~/.haunt` (fully resolved, so a symlinked alternate home cannot alias past it). This closes a real incident: a smoke test with `HAUNT_HOME` pointed at a worktree's `.smoke-home` wrote that path into the operator's real `~/.claude/settings.json` for all six hook events; the worktree was deleted later and memory capture stopped silently for three days. `haunt bootstrap` now skips the bind and reports it under `HOST BIND SKIPPED`; `haunt install` and `haunt cursor-install` exit non-zero; `haunt doctor` prints `NOT re-merging hosts` instead of running its repair merge. A deliberate alternate-home bind is still possible with `haunt install --allow-alt-home` or `HAUNT_ALLOW_ALT_HOME_HOST_INSTALL=1` (exactly `1` — nothing else counts as consent).

`haunt doctor` detects dangling hook commands. Every haunt hook command found in every supported host's config is checked for existence *and* executability, and each failing host + event + path is listed under `[dangling hooks]` with the fix. Entries are recorded per event rather than deduplicated per command, so a single dead wrapper is reported as the six (Claude Code) and seven (Cursor) dead events it actually is. The check only stats; `diagnose()` still writes nothing.

Hard purge erases bytes, not just rows. The erasure transaction runs with `secure_delete` on, merges the FTS index so erased terms do not linger behind delete markers, then rebuilds the database file and truncates the WAL. A canary planted before a purge is absent from the namespace file and its sidecars afterwards. The report and `haunt delete` carry `bytes_overwritten`, false when a concurrent reader blocked the rebuild.

Purge also sweeps the namespace backups haunt writes itself. `namespaces reconcile --apply` and `namespaces retire --apply` each leave a full plaintext copy of a database under `HAUNT_HOME/backups`, so the erasure was true in the live file and false one directory away. Purge now runs its whole erasure on every such backup that holds the row — content, correction lineage, purge-safe session rekeying and metadata sanitization, and the privacy head rotation — and rebuilds each file it touches, matching on the memory id reconcile preserves when it copies rows. The head rotation also runs on the backups that never held the row, because the head is what a restored file answers with rather than a property of the erased row: leaving it alone made the one backup the purge had nothing to erase from into the way back in. A restored backup is therefore a database the purge has already happened to: it refuses a bundle exported before the purge instead of importing the erased row back. A file counts as erased only after the sweep re-reads it — integrity and foreign-key checks, the row's absence, a moved privacy head, and a raw byte scan for the erased values — so `backups_unerased` names anything unproven, with the reason, and CLI, MCP, and console all surface it. A candidate the sweep declines to rewrite is named too: refusing to touch a backup that is hard-linked elsewhere, no longer mode 0600, or no longer a regular file is not evidence the row is not in it, and `backups_scanned` counts every candidate so the report can be checked against the directory. The byte scan looks for the erased values as stored, so it catches a transcribed copy and not a re-encoded one; session metadata is decoded through its JSON layers before the sanitizer decides, so a value one `json.loads` deep is removed rather than merely unfound. Sweeping invalidates the sha256 the migration report recorded for that backup. Copies haunt did not write — exports, an operator's own copy, filesystem snapshots, removable media — and blocks the filesystem already released remain out of reach; SECURITY.md states the boundary.

Reconcile's authorized digest covers `embedding_jobs`. The apply copies those rows verbatim, `attempts` and `last_error` included, and they were outside `content_state_digest`: any drain running between the dry run and the apply wrote values the operator never authorized — an operator's `haunt bootstrap` or `haunt maintenance`, or the 32-row drain inside an ordinary non-deferred write. There is no background drain, which is why dry run and apply must be run back to back. The table is hashed but still not merged row-for-row, so a queue-state disagreement does not manufacture a content collision.

The capture-policy embed exclusion is persisted on the row (`memories.skip_embedding`, schema v13). It used to exist only as an `observe()` parameter, so it was admission-time only and a `reembed()` or model change put every excluded Bash/Read/ceremony row straight back into the vector index. `reembed()`, the queue drain, and reconcile's requeue all honour the stored flag; `reembed()` reports `skipped`. Existing rows are backfilled from the signature they already carry (no vector, no queue row, non-blank content), which never marks a row that was embedded or queued and does miss exclusions whose queue row was manufactured later by the v3 migration or a model-less `reembed()`.

The test fixture stopped gating its model cache on a dead `/workspace/lore` path, so a populated `$HAUNT_HOME/models` is reused instead of re-downloading the model per test, and it no longer deletes `HAUNT_FTS_ONLY` — CI's FTS-only run now really is FTS-only. CI gained a `test-hybrid` job so sqlite-vec and the embedding path still get exercised.

Dashboard Host/Origin/launch-token (#66): `haunt dash` still defaults to 127.0.0.1, rejects untrusted `Host`, requires a minted launch token (`X-Haunt-Token` or `?token=`) on every `/api` route, and validates `Origin` on DELETE/contradict. `--allow-remote` without that token refuses to start (empty token → every `/api` route 401). HTML index still loads without the token. Loopback injects the token into the console HTML; `--allow-remote` / non-loopback bind does not embed it (stdout only). `--allow-remote` is unsafe without the token; namespaces are not authorization.

New timestamps keep microseconds (or finer) and stay UTC. Opening a namespace runs a schema-versioned one-time rewrite of offset/naive clocks; queries do not rewrite history. Newest-procedure / latest-row picks break ties with `rowid`, not second-resolution `created_at` alone. (#67)

MCP and CLI reads/mutations use `open_existing`: unknown namespaces fail loud and do not create a `*.db`. Only `init`, first `observe`, procedure write, and bootstrap create. (#68)

Dashboard POST contradict rejects non-JSON (415), invalid/non-object JSON and non-string `replacement` (400) without setting `valid_to`. `Store.contradict` raises `ValueError` if `replacement` is not a string or null. `HAUNT_FTS_ONLY=1` / `HAUNT_EMBED_MODEL=off` bootstrap no longer fatals on a failed sqlite-vec probe; layout + default namespace still come up FTS-only, without downloading BGE-M3. Doctor treats sqlite-vec as optional in that mode. (#64)

Honesty pack (#61): dashboard `openDetail` escapes every `.val` field (including `session_id`); host hook/settings merge fail-closed on malformed JSON; `Store.contradict` is one transaction and refuses already-superseded rows; timeline fills `k` current memories; generated wrappers quote `HAUNT_HOME`; CLI timeline / worldview size params use the same clamp helpers as recall `k`.

Doctor honesty: `{host}.hooks` fails when the planted haunt-hook path is missing or is not the expected wrapper. Leaf name alone is not enough. Runtime hook fail-open is unchanged.

DELETE `/api/namespace/{name}/memory/{id}` and POST contradict 404 `unknown namespace` on a missing namespace (`Store(..., create=False)`). A typo no longer creates an empty DB, then 404s `memory not found`.

GET `/api/recall` (all-namespaces) attaches a non-empty `errors` list when a registered namespace fails to open or search, and the console recall meta surfaces those failures instead of only `N hits (all namespaces)`.

Release-gate hardening (storage isolation honesty, private HAUNT_HOME modes, mcp>=2 pin, loopback dashboard bind, dashboard XSS/GET-create/limit clamps, Authorization Bearer hook redaction).

## 0.2.0 — 2026-08-24

Naming cleanup. Product name is **haunt** only.

- Removed `lore` / `engram` console scripts and `~/.haunt/bin` wrappers. Entry points are `haunt`, `haunt-mcp`, `haunt-hook`, `haunt-hook-claude`.
- Host doctor accepts `haunt-mcp` / `haunt-hook` only. `lore-mcp` in `mcp.json` is not a haunt command.
- User-facing home is `~/.haunt` / `HAUNT_HOME`. Dropped `LORE_*` / `ENGRAM_*` env aliases and the `~/.lore` fallback.
- Install from git: `pip install git+https://github.com/moderatesoup/haunt.git`. `pip install haunt` on PyPI is not this project (mikepqr's stow).
- Deleted stale `WIRING_REVIEW.md` (PR #2, six-tool era).
